# `/demo` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `/demo <issue>`: the agent drives the developer's local app through the ticket's
acceptance criteria, records one clean take, and posts the video (or screenshots) with a chapter
list as one Redmine comment after explicit approval.

**Architecture:** The skill (`skills/demo/SKILL.md`) orchestrates. Four small Node scripts do the
browser and video work: `session.mjs` (sign in once, check the saved session), `run.mjs` (replay a
scene script to rehearse, record or screenshot), `assemble.mjs` (trim, encode to the size limit,
contact sheet, comment text) and `lib.mjs` (pure functions the other three share). The scene
script is a JSON file the agent writes while rehearsing; recording replays exactly that file.

**Tech Stack:** Node 18+ ESM, Playwright 1.61.1 (Chromium), ffmpeg, `node:test`, rmine v0.7.0+.

**Spec:** `docs/superpowers/specs/2026-10-23-demo-design.md`

## Global Constraints

- Public repo: no company, product, URL, account or ticket detail in any file, test fixture or commit.
- No em dashes in anything new. Short sentences, matching the existing skills.
- Node 18+ and ffmpeg on `PATH`. Playwright pinned to exactly `1.61.1`.
- Install line, as clip-studio: `npm install --prefix ${CLAUDE_PLUGIN_ROOT}` then
  `npx --prefix ${CLAUDE_PLUGIN_ROOT} playwright install chromium`.
- The skill never starts servers, touches a database, seeds data, or handles a password.
- Recording only starts in a browser that is already signed in.
- Comment only: `rmine issue comment <id> --file <comment-file> --attach <file>` (repeatable `--attach`).
- Post only after an AskUserQuestion yes for the exact text and files, in this run, for this ticket.
- Per-user state and all output live outside the product repo and outside the plugin.
- Comment body, exactly:
  ```
  Demo of <ticket subject>, recorded on <branch> at <short sha>.

  0:00 <scene 1 caption>
  0:42 <scene 2 caption>

  Reply with a time and what's wrong, and I'll pick it up before QA.
  ```

## Decisions this plan makes (the design left them to the builder)

1. **Playwright 1.61.1, not clip-studio's 1.63.0.** 1.62.0 raised the floor to Node 20
   (`npm view playwright@1.62.0 engines.node`), and this machine's default `node` is 18.20.4 from
   `~/.tool-versions`. A product repo with no Node pin runs `/demo` under 18. 1.61.1 is the last
   release on `>=18` (June 2026). Cost: a second Chromium download next to clip-studio's.
2. **Captions and pointer drawn in the page.** This machine's ffmpeg has neither `drawtext` nor
   `subtitles` (`ffmpeg -filters` lists none), so the ffmpeg route is closed anyway.
3. **Signed-out detection is "a visible password field".** Generic across apps, needs no
   per-app config. `session.mjs check` and every recorded step use it.
4. **State directory:** `${XDG_STATE_HOME:-~/.local/state}/rmine-skills/demo/<repo>/`, mode 0700.
   `<repo>` is the basename of the directory holding `git rev-parse --git-common-dir`, so every
   worktree of one repo shares one session. Inside: `settings.json` (url, size limit),
   `session.json` (storageState, mode 0600), and `<issue>/` for output.
5. **Size limit** is a per-user setting in `settings.json`, `max_attachment_mb`, default 5.
6. **Lockfile not committed**, following clip-studio's `.gitignore`; the exact pin carries it.

## Scene script format (the contract between rehearsal and recording)

```json
{
  "issue": 123,
  "subject": "Ticket subject",
  "mode": "video",
  "viewport": { "width": 1280, "height": 800 },
  "scenes": [
    {
      "caption": "Filter the list by status",
      "criterion": "Acceptance criterion text this scene proves",
      "start": "/items",
      "steps": [
        { "click": { "role": "button", "name": "Filters" } },
        { "fill": { "label": "Status" }, "value": "Open" },
        { "press": "Enter" }
      ],
      "expect": [
        { "visible": { "text": "3 results" } },
        { "url": "status=open" }
      ]
    }
  ]
}
```

- Locator: exactly one of `role` (+ optional `name`), `label`, `text`, `placeholder`, `testId`, `css`.
- Steps: `goto` (path), `click`, `hover`, `fill` + `value`, `select` + `value`, `press` (key), `wait` (ms).
- Expect: `visible`, `hidden` (locator), `text` (substring of the page), `url` (substring).
- `start` is a path joined to the saved URL. `mode` is `video` or `screenshots`.

## Review Focus

1. **Session expired between rehearsal and recording.** The app redirects to its login page. Expect:
   the run stops at the first password field, no video kept, message says sign in again.
   Pinned in Task 3 (`record stops on a password field`).
2. **Uncommitted changes in the product repo.** The short sha does not describe what was filmed.
   Expect: the comment line reads `recorded on <branch> at <sha> with uncommitted changes`.
   Pinned in Task 1 (`renderComment marks a dirty tree`).
3. **A scene check fails mid-take.** Expect: exit non-zero, the failing scene's number and caption,
   a screenshot and aria snapshot of what was on screen, and the partial video deleted so it cannot
   be posted. Pinned in Task 3 (`failed expect deletes the video`).
4. **Video too large even at the quality floor.** Expect: `assemble.mjs` exits 5 with the duration
   and the bitrate it would need, and writes no MP4. Pinned in Task 1 (`planEncode refuses below
   the floor`) and Task 4.
5. **App not running.** Expect: `session.mjs check` exits 3 with the URL it tried, distinct from
   signed out (exit 4). Pinned in Task 2.

**Spike results (2026-10-23, against a fixture app; the user has no local app to record):**

1. No pointer in Playwright's video. Confirmed: the plain take shows none.
2. The in-page caption and pointer survive a navigation when re-applied on `load`. Confirmed.
3. A filled dot hides the label of the button it clicks. The pointer is a hollow ring instead.
4. Size: a 7 s take of a simple page is 42 KB at CRF 28. Text is still readable at 80 kbps.
   A simple page can't set a real floor, so 150 kbps stays until the dry run shows otherwise.
5. **Not in the plan before:** the first take in one run lost its first 2.5 s. The video was 6.1 s
   against 8.6 s on the clock, and scene 1's click never appeared. A second run lost nothing, and
   an idle page doesn't drift (8.2 s on the clock, 7.96 s of video). So frames can go missing at
   the start, never in the middle. Chapter times are therefore counted back from the video's end
   (the context close), and a take whose scene 1 would start before 0 s fails with "the recording
   started late, run it again".
6. Because CRF 28 output is so much smaller than expected, `assemble.mjs` encodes at CRF 28 first
   and calls `planEncode` only when that result is over the limit.

### Task 3: `run.mjs`: rehearse, record, screenshot

**Files:**
- Create: `skills/demo/scripts/run.mjs`, `skills/demo/scripts/overlay.js` (the init script)
- Test: `skills/demo/scripts/run.test.mjs`

**Interfaces:**
- Consumes: `validateScript` (Task 1), `isPasswordVisible` (Task 2), `startFixture` (Task 2).
- Produces CLI `node run.mjs <rehearse|record|screenshots> <script.json> <state-dir> <out-dir> [--scene N] [--steps K]`:
  - Always validates the script first (exit 2 with the errors).
  - `rehearse`: headless, no video. Runs all scenes, or scene N up to step K. Prints one line per scene, `PASS n caption` or `FAIL n caption: reason`. After the last step run, writes `look.png` and `look.aria.txt` (`page.locator('body').ariaSnapshot()`) to out-dir and prints both paths. This is how the agent sees the app.
  - `record`: headless, `recordVideo` at the viewport size. Before each scene: set caption, `goto start`, hold 1 s. Each click and hover moves the drawn pointer to the target's centre over 600 ms, then acts, then pauses 700 ms. After `expect` passes, hold 1.5 s. Writes `raw.webm` and `chapters.json` (`[{scene, caption, criterion, start, end}]`, seconds from video start).
  - `screenshots`: like record without video; after each scene's `expect`, `scene-NN.png` with the caption shown and the pointer hidden. `chapters.json` with `start: null`.
  - Any failed step or expect (5 s timeout): exit 1, print scene number, caption and reason, write `failure.png` and `failure.aria.txt`, and delete `raw.webm`.
  - A visible password field at any scene start or after any step: exit 4, delete `raw.webm`.
- `overlay.js`: added with `context.addInitScript`; exposes `window.__demo.caption(text)`, `window.__demo.pointer(x, y)`, `window.__demo.hidePointer()`; draws a fixed caption bar at the bottom and a pointer dot that follows `mousemove`. `run.mjs` re-applies caption and last pointer position on every `load`.

### Task 4: `assemble.mjs`: encode, contact sheet, comment

**Files:**
- Create: `skills/demo/scripts/assemble.mjs`
- Test: `skills/demo/scripts/assemble.test.mjs`

**Interfaces:**
- Consumes: `planEncode`, `renderComment`, `formatTime` (Task 1); `raw.webm`, `chapters.json`, `scene-NN.png` (Task 3).
- Produces CLI `node assemble.mjs <out-dir> --subject <s> --branch <b> --sha <sha> [--dirty] --limit-mb <n>`:
  - Video mode: trims to the first scene's start, shifts chapter times by the same offset and rewrites `chapters.json`, encodes `demo.mp4` (H.264, `yuv420p`, `+faststart`, no audio) per `planEncode`. If the result still exceeds the limit, one retry at 85% of the bitrate, then exit 5. `tooBig` exits 5 before encoding, printing duration and needed kbps. Writes `sheet.png`: one frame from the middle of each scene, tiled with ffmpeg `tile`.
  - `--parts 2`: the split fallback. Cuts at the scene boundary nearest the middle into
    `demo-1.mp4` and `demo-2.mp4`, each encoded against the full limit; chapter times in
    `comment.md` restart at 0:00 under a `Part 1` / `Part 2` line.
  - Screenshots mode (`chapters.json` starts are null): no encode; checks each PNG is under the limit.
  - Always writes `comment.md` from `renderComment` and prints the paths of `comment.md` and every file to attach, one per line, prefixed `attach: `.
